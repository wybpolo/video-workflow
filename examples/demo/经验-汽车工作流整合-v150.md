# 经验总结与整合说明（2026-11-07）

## 一、我方现状自评（v1.5.0 首版样片，用户打分 70）

样片证明：没有 car-video-production 技能，靠现有栈（总控 A–I 路线 + ffmpeg-skill + dataviz + rea-video + 两份文档的 33 条手法）也能完成同类汽车技法片。扣分项（自查）：

1. **追踪是全片最弱一环**：CSRT 在 7 秒涉水镜头后段框体收缩到车身中部——当时只做到「能跑」，没有追踪纪律（丢失处理、轨迹规范、分段重初始化、漂移复核标准）。
2. **无计划契约**：组装脚本即兴写就，镜头/来源/主张没有统一清单；时长靠各段相加，xfade 重叠吃掉 2 秒是事后才发现的（计划阶段用整数帧排就不会）。
3. **验收停留在参数层**：只核了时长/响度/平台规格，没做完整解码帧数核对，也没看切点前后帧（仓库的质量文档指出：历史 v1 末尾 5 帧混入异物正是只看中点漏掉的）。
4. **声音缺位**：样片无旁白、只有片段原生声——技法演示没有解说引导，信息全靠画面标签。
5. **检索名实问题**：卡库是字段/关键词检索，我一度在汇报里把它与「RAG」并称——它离语义召回有距离，需要明确的后端声明来对齐预期。

强项（保留）：生成与渲染引擎层完整（E 原生生成/Multiplane/HyperFrames/剪映草稿）、rea-video 自动拆解、dataviz 图表纪律、文档 B 的证据链（仓库的叙事文档只源于乘用车那份，卡车证据链是我们合并进去的增量）、每步实测留档的习惯。

## 二、car-video-production 的可取之处（逐项核对后）

这是一个「契约+纪律」型技能包（SKILL.md + 10 篇 references + plan 模板 + 2 个标准库脚本，116K），**不带引擎**：它的 ima RAG 服务、Tracker 工作台、卡片前端都在用户 Windows 本机上，不随包迁移；包内 HyperFrames CLI 版本（0.9.19）比我们装的新。真正能搬走的是四类资产：

| 资产 | 内容 | 我们的缺口 |
|---|---|---|
| **plan 契约 + check_plan.py** | car-video.plan.v1：整数帧时间线、sources 指纹/复核范围/车型核验、claims 四类挂证据；检查器校验主镜头连续覆盖、素材时长够用（含 hold/speed 换算）、事实主张必有证据 | 无任何计划契约，组装靠即兴脚本 |
| **verify_video.py + 验收分级表** | 完整解码+帧数/尺寸/帧率核对出 evidence JSON；明确 technical_pass ≠ 画面通过，验证分五级记录 | 只有 ffprobe 级核对，无帧数级验收、无分级记录习惯 |
| **跟踪方法学** | 光流 PyrLK+前后向误差+RANSAC 相似变换（其工作台默认引擎）、模板 NCC 备选；归一化 xywh+参考画面、裁切后同步变换轨迹、丢失隐藏不显示陈旧框、不跨丢失插值、原始轨迹与平滑参数并存、bbox≠抠像、分数≠准确率 | 只有 CSRT 单引擎 + 无纪律（v1 样片实证） |
| **检索与批量纪律** | 后端三分支（已有服务/本地拆镜/建最小索引）与诚实命名、查询分解式（主体+部位+动作+机位）、入选复核清单（首中尾+切点+车型+干净范围+指纹）、批量台账逐条记失败与缺素材、缓存失效规则 | 卡库有检索无后端声明；批量只有目录约定无台账规范 |

另外吸收的细节：四种时间不叠加偏移（原片/预览/分析/整片）；剪映三状态独立（结构过/打开过/导出过）与草稿唯一命名、禁 allow_replace 覆盖未知目标；图表 claims 的条件/单位/精度记录；「亮区占比不是照度、像素不是物理尺寸、异车型画面不是同配置证据」三条防伪断言。其 storytelling 手法表源于同一份《拍车叙事手法》docx，与我们的 33 条互为印证，并多一列逐项「主要检查」，已并入 J 路线检查要点。

**不搬的**：local-project.md 的 Windows 路径与本机服务地址（只在用户本机成立，将来在本机跑 J 片时按图索骥）；其花叔汽车扩展代码（在本机 DEMO 工程内，未随包）；ima 接口细节（本机未部署该服务前不接入，只预留字段适配）。

## 三、整合落地（已执行）

1. `check_plan.py`、`verify_video.py` 原样 vendor 进 video-studio/scripts/（已实测：前者对其示例 plan 结构检查通过）。J 路线定为：**plan 先行 → check_plan 过门 → 按 plan 组装 → verify_video 收尾**，交付说明按五级验证如实标注。
2. `track_highlight.py` 升 v2：默认引擎换光流（PyrLK+前后向+RANSAC），CSRT 降为备选；轨迹输出 car-track.v2（归一化 xywh + 状态 + 原始/平滑双份）；丢失帧隐藏全部覆盖物。同片同段实测对照：光流中段保尺度优于 CSRT、末段滑出车体，CSRT 末段收缩到车身——结论写回路线：**分段重初始化 + 全段复核**为标准做法，任何单引擎不承诺准确率。
3. `car_lib.py` 入库卡新增 retrieval_backend=local-scan 与 review_status 字段；J 路线写明结构化检索不称语义召回，接 ima/向量时再换后端声明。
4. 总控 J 路线补：plan 先行、验收分级、批量台账、检索后端声明、数据防伪三条；版本号保持 v1.5.0（未推送，整合后一并待用户拍板）。

## 四、demo v2 的改进对照

针对自评五项逐项改：plan.json 先行并留检查证据；追踪段用光流 + 分段重初始化（3.0s 起段 A、7.0s 重新定位起段 B）且全段抽帧复核；加旁白解说串起技法；验收跑 verify_video 并抽切点前后帧；时长按整数帧计划（目标约 55s），不再事后缩水。
