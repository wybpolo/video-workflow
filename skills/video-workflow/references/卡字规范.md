# 卡字规范（讲解类成片的画面落点纪律）

适用：一切「先有旁白、画面追随旁白」的讲解类成片——A 艺术解说、B 通用设计中的讲解段、J 汽车视频的讲解段落、PPT 转视频。核心命题：**画面动作要在旁白关键词被念出的那一刻到位**，不是大约同时，更不是说完才动。

方法来源：kazi（syydaniel/kazi，代码 MIT / 文档 CC BY 4.0，本规范为提炼重述）+ 编辑台的关键词导演法（其仓为个人非商业许可，仅方法借鉴、未引用文本）。它取代并升级原「词锚」方法条目：词锚是意识，本规范是可执行契约 + 可量化验收。

## 一、稿子先行：标记语法

写稿时就把落点信息标进稿子（每句至多一个关键词）：

- `*关键词*`：本句的落点词，画面动作对它到位。
- `{念法=>字幕}`：念法与显示字不同时分离（如 `{百分之三十=>30%}`），时间按念法逐字算、字幕按显示字分配。
- `| 0.4`：句后停顿秒数，写进时间表不靠后期猜。
- `[段落名]` 分节、`@gap 名称` 命名空白段（演示/留白）。
- 写稿期用 `video-studio/scripts/lint_script.py` 查：一口气过长、字幕超 16 字、一句多关键词、估时长。

## 二、时间表契约 timeline.json

配音完成后必须生成逐字时间表，画面里一切与旁白有关的时刻都从表里查，禁止按字数/语速估时（实测：按字数估，78 句的片子第十句就差 3.7 秒；句内均分中位误差 0.16 秒、最差 1.2 秒，落点差 0.2 秒观众就觉得没卡上）。

字段：`total` 总秒数；`lines[]`（start/end、say 念法、show 字幕、words 逐字起止、cap 字幕逐字起止且关键词带 k=1）；`sections`、`gaps`、`keywords[]`（word + 首字起点 t）。

我们的生成路径：TTS 逐句合成 → faster-whisper 词级时间戳（word_timestamps）组装本表（kazi 原实现用 Qwen3-ForcedAligner，但其管线是苹果 MLX 绑定，本机不用；原理相同：强制对齐，不是估算）。换配音 = 全部锚点失效，重跑时间表（词锚旧规矩继续有效）；同词多次出现标第几次。

## 三、时间常数（基准 60fps，括号内为 30fps 换算）

| 项 | 值 | 依据 |
|---|---|---|
| 动作到位 hit | 关键词首字起点 **前 3 帧**（30fps 前 1–2 帧，即约 −50ms） | 声音超前约 45ms 可察觉、画面超前约 125ms 才察觉（ITU-R BT.1359），宁早勿晚 |
| 容差 | 提前 6 帧 ~ 推后 1 帧（30fps：−100ms ~ +17ms） | 晚 2 帧以上接近察觉门限 |
| 新元素出现 appearBy | 至少早于关键词 12 帧（约 200ms） | 眼睛扫过去需要约 200ms |
| 动作时长 | 小元素 6–12 帧、卡片约 18 帧、跨屏 27–42 帧（按 60fps，30fps 减半） | 时长随距离/体量增长才有重量 |
| 弹簧 | 阻尼比约 0.75（过冲约 3%）；透明度/颜色不过冲；**文字永不变形** | 默认弹簧过冲 16% 像玩具 |

镜头移动 0.6–1.2 秒、两端柔和曲线；一屏新增信息不超过 4 块；屏幕上的字只放关键词，整句交给字幕。

## 四、画动词，不画名词

名词画出来是插图，动词画出来观众才看懂。先找关键词对应的变化，再定画法，落点 = 变化完成的那一帧：

| 动词 | 画法 | 落点 |
|---|---|---|
| 变大/涨/增加 | 撑开、柱子长高，旁留参照物 | 到位帧 |
| 变小/降/压缩 | 收紧、变矮，被挤掉的淡出 | 到位 |
| 分开/拆 | 沿中线裂成两半往两边退 | 两半完全分开 |
| 合并/组合 | 几块靠拢、边线消失 | 合成一块 |
| 筛选/只留下 | 大部分暗下去，留下的保持亮（即 J 路线高亮式） | 暗下去完成 |
| 连接/依赖 | 线一根根接上 | 最后一根接上 |
| 复制 | 从原物里滑出一个一样的 | 新的到位 |
| 替换 | 旧的推出、新的同位进来 | 新的到位 |
| 循环/重复 | 走一圈回起点，第二圈加速 | 回到起点 |
| 比较 | 并排，差的部分高亮 | 高亮出现 |

## 五、关键词独立事件（口播/讲解的前景文字层）

重点词不只是句内变色，要独立成事件：从逐字稿里挑 2–4 字的高冲击词与关键数字，在它被说出口的时刻以显著大于正文的字号弹出（spring 入场），独立进退场。按语义分工（决定卡面形态）：关键词/数字→大字弹出；定义→揭示卡；结论→结果锁定（状态卡与结果卡并置，不互相覆盖）；裁决→印章式；引言→引文框；问题→张力字；警告→边界警示。可见文字滚动累积上限三行，首行不因新行出现就消失（除非明确退场/替换/碰撞）。没有值得强调的段落就留空，不硬塞填充卡。

## 六、字幕

每条 ≤16 字按标点切（逗号句号去掉、问号叹号保留）；语速 ≤9 字/秒（Netflix 简中规范）；字按真实念时由浅变深，关键词念到时变色、每条至多一个。字幕轴与时间表的一致性用 `video-studio/scripts/caption_check.py` 量。

## 七、验收：卡字率（讲解片新增验收门）

`video-studio/scripts/kazi_check.py 成片.mp4 --keywords keywords.json --json check.json`（keywords 为 [{word, t}]，t 取时间表）。判据：关键词窗口 [t−0.35s, t+0.15s] 内的画面平均动量 ≥ 其前一秒的 1.5 倍且多出画面 0.1% 以上，算卡上；报告同时给出随机基线与「高出随机」lift。**匀速一直在动的画面不给分**——要的是关键词那一下明显多动一下。它与 verify_video（技术门）分工：后者管帧数/解码，本门管音画同步。逐段渲染时用 --offset 分段量。

常见卡不上三因：一句只在开头换卡、关键词在句中无事发生；整段匀速运动、关键词处无区别；动作有但晚了（说完才动）。

## 八、附带纪律（同批吸收）

- **剪后时间重映射**（编辑台方法）：口播素材剪气口/口误后，所有字幕与事件时间戳必须经剪切映射表（cut-map）统一换算到新时间基，禁止新旧时间基混用——F 路线处理口播素材时执行。
- **音效覆盖审计**（编辑台方法）：每个可见节拍要么有音效 cue、要么在计划里写明静音理由；音效与画面动作共用同一张打点表导出，保证峰值同帧（kazi 的声画同源打点同理）。
- 旁白小工具（kazi，MIT，已 vendor）：`pace.py` 只动静音的停顿规整、`tempo.py` 变速不变调——VO 适配镜长时优先于整句变速。
